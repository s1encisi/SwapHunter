# 四职业经济与存档规则

本文件记录 D1.1 实现规则版本 2（存档版本 6），不是旧 T01 的定价。下表已经本轮原生隔离验收以实际 Store 交易接口逐章核对，共4职业×12章=48行；不包含刷关或可选收益。它证明账面可行，不等于实战或真人平衡结论。

- 新档 0 信用点。共享账户拥有武器、技能、库存和章节记录；四职业分别保存双枪、每枪免费配件、一职业技能、一通用技能、两种不同道具预设。买其他职业商品允许，装备仍校验职业资格。
- 卡宾全档保障一次；每职业入门枪（泵动/重突/三连发/榴弹）及该职业任选一基础技能分别保障一次；盾或刀的通用技能保障全档一次。已拥有资产只标保障满足，不返现。切职业不发钱或补库存。
- 开局上架 0/1/2/3/9；第三章首通后上架 4/6/8/10；第六章首通后上架 5/7/11。上架不等于拥有，成功结算不再赠枪。
- 武器价格按 ID 0..11：120、120、140、140、120、180、180、240、220、160、220、200。卡宾的免费来源是保障，商品价格不是 0。
- 八项职业技能及盾/刀基础均开局上架，基础 100，1→2 为 100，2→3 为 160；同职业的两技能可独立购买，没有互为前置条件。通用槽只装备盾/刀之一。
- 医疗包 20/恢复40HP/最多携带2；弹药包25/双枪各两弹匣/最多1；应急护甲25/40护甲/最多1。携带由两不同类型槽选择，库存共享；道具不足按实际库存带入，空库存不阻止部署。场地补给不进入永久库存。
- 成功基础50；首通额外150+15×零基章节ID，即首通总200、215……365；成功可选+40；失败/退出0。重玩只有基础50与实际完成的可选项，不重发首通；不按击杀发钱。

## 事务与验收入口

`ExpeditionStore(folder,true)` 只打开 `expedition-v6.json`。根入口使用独立 `Expedition-Tactical-v6` 目录；不自动打开v4正式档或T01 v5。默认单参数构造继续用于明确的旧模式/旧夹具。

采购先独立保存；出发保存配装、技能等级、三库存与两槽携带快照。运行中不扣永久库存；死亡只累计死亡，重试同runId累加尝试并恢复快照。退出与中断恢复采购后库存；成功在一个提交中扣实耗、加奖励、写首通和回执。采购编号+商品+数量去重；写失败保留内存与主档。

集中入口 `TacticalStorageChecks.Run(fixtureRoot, check)` 调用生产 Store API，在新GUID隔离目录生成四职业48行采购/结算记录，并输出独立 `economy-paths.json` 和 `economy-paths.md`。覆盖跨职业共享/资格、独立预设、两种不同道具槽、三库存死退成结算、支付与写失败、重复结算及纯迁移预览；不重复整套旧QA，不建立真人战斗或FPS结论。本文件不预先宣布该集中检查已经通过。

## 旧档仅预览和候选

`TacticalMigrationPreview.Preview(sourceJson, sourceLabel, explicitlySelectedCopy, r?, S?, D?)` 只解析用户明确选择的副本文本，不自行搜索/读取路径，不创建Store。v4保留章节/拥有/成绩，旧刀0/1/2/3映射新1/2/3/3，旧盾映射1；旧专精效果不进入新档。名义价目仅作说明，实际S、D和r未知时保留 `UnknownHistory`，不补0。

T01 v5已使用信用点，余额和已购医疗库存原值映射；已知医疗采购回执保留，不套用研究点兑换率，不补发新首通差额。每职业配件和可用预设保留；缺少合法装备的职业保留未就绪配置，等待正常保障，不暗送资产。

`BuildCandidate(preview, approved)` 仅在明确审阅同意且映射/余额已明确时生成通过Validate的内存v6候选，仍不写正式档。旧行动回执标注 `historical/sourceVersion`，不伪造新奖励分项或旧尝试次数；预览和候选可反复生成，不重复发钱。实际导入仍需用户另行确认、原档备份和专门幂等导入步骤，本实现没有自动导入入口。
