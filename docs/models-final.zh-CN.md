# 新模型版本：资源与接入

这一版将游戏运行时的角色、敌人、Boss、第一人称手臂、十二把枪和主要场景物件换为新模型。职业页和武器页继续显示图标、可旋转模型及数字/属性条。实际画面与验收结果以本版报告为准。

## 替换范围

| 部分 | 新模型与接入方式 |
|---|---|
| 四职业 | Quaternius Animated Characters 中的四种不同身体，保留真实骨架和动作 |
| 普通敌人与训练目标 | 新人物模型；移动、射击、受击与死亡读取原游戏状态驱动真实动作 |
| Boss | George 机甲及其骨架动画，技能时机、伤害和阶段仍由原 Boss 系统控制 |
| 第一人称 | 新身体提取的双臂网格，真实骨链求解持枪及装填触点 |
| 十二把枪 | Quaternius 枪械和 Kenney 科幻枪组件，独立枪体与枪口、握点、机械活动部件 |
| 飞刀与护盾 | CC0 Bayonet 刀体；新制作的项目自有护盾网格 |
| 场景 | 十二章、经典/教学区域的地板、墙体、柱梁、箱体、门、锚点、控制台、补给与背景建筑 |

判定圈、弹道、灯条、准星等操作反馈继续使用程序几何。旧模型原件保留供追溯，运行中的上述模型通过新资源工厂绑定。

## 设计取舍

新资产都是视觉子树：环境模型拟合已有物理代理，导入的外部碰撞器和脚本不参与玩法。角色的根位移由原控制器管理，骨骼动画不改变换位结果、导航位置或伤害判定时机。头部和躯干判定点随新模型相应骨骼定位；头部命中区域是原有弱点范围，不等于整个夸张比例的头部网格。

枪械以统一米制和朝向导出，握点、枪口与装填节点是明确的契约。预览图标和实战枪体读取同一新模型来源，避免界面与游戏不一致。源模型、变换、原件与派生文件哈希记录在三个来源索引中。人形每份有17段源动作、George有20段；游戏按现有状态选择所需动作，并非每段源动作都对应新增玩法。旧 Blender 材质的颜色从原节点读取并补入 GLB，保留网格和动画数据。

## 运行与查看

Unity Hub 选择仓库下的 **Game** 目录，使用 Unity **6000.3.25f1**。打开 Assets/_SwapHunter/Scenes/SwapHunter.unity 后进入 Play；地图由运行时代码构建。普通打开与构建不需要 Blender。

Windows 包完整解压后，正常运行 SwapHunter.exe；快速看全内容可使用包内的 快速体验.cmd，它使用独立演示档。建议依次查看职业页、武器装配页、第5/7/12章与 Boss。

## 实际复现入口

- ActorVisualRig.cs：新身体、骨骼挂点、动作播放与根位移控制。
- ActorEquipmentVisuals.cs：新盾牌、飞刀、枪械挂载。
- WeaponVisualCatalog.cs、PlayerWeaponPresentation.cs：枪体来源、第一人称骨链和装填。
- FinalEnvironmentModels.cs：场景视觉与已有碰撞代理的绑定。
- Tools/VisualAuthoring/characters-source-index.json、weapons-v2-sources.json、final-environment-source-index.json：来源与转换记录。
- THIRD_PARTY_ASSETS.md/json：许可及素材作者；外部模型不作为个人原创建模成果。
- ModelsFinalQA.cs：本次模型相关的必要原生验收；模型结果不能替代真人试玩结论。

AI参与代码实现、模型转换脚本与文档整理；用户负责需求、玩法与方案决策。面试中应以自己能解释和复现的设计、调试与验证工作表述贡献。
