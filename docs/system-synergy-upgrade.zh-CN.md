# SwapHunter 系统协同升级方案

日期：2026年10月14日  
方案编号：SSU-01  
基础版本：已发布 v0.6.0；方案开始时本地 main 为 0d7408d。  
依据：《换位猎手系统改进建议》内部版和现行实现。  
状态：待实施的内部方案。本次任务只创建分支并编写方案，不修改玩法，不混入求职投递版设计文档。

## 1 升级目标与首选路线

核心目标是让玩家在关外形成可理解的配装选择，在关内用一致的动作、伤害和空间规则执行选择，完成任务后得到能解释的资源结果，再调整下一次配装。

首选路线分三步：

1. **先统一规则。** 固定Q的动作衔接，分开伤害与防御维度，明确Boss控制和转阶段的契约，让图鉴、战斗与补给使用同一份有效参数。
2. **再连接系统。** 复用已有独立演示，完成“查看商品—定向试用—回到商品—自主采购”；用合法配装路线说明武器、技能与关卡的用途。
3. **最后单项调参。** 首轮冻结主要数值，用实际选择、耗用和时间记录决定是否调整。行为规则本身改变难度时，先检查直接影响。

协同不等于所有能力都互相增伤。互斥、固定世界位置、自伤和携带上限继续提供取舍。本期改善的是规则可预测性、选择依据和系统间反馈。

### 1.1 决策摘要

| 本期确定改进 | 首轮保持 | 有证据后再试 |
|---|---|---|
| Q取消动作固定化；Boss空间技能不被普通硬直整体冻结 | Q范围22米、准备0.08秒、冷却3.5秒；现行武器伤害与技能等级值 | 只针对新增行为造成的问题，调整对应预警或收招 |
| 明确标记类型与三类盾的作用 | 标记5秒、后续枪弹和普通近战加20%；爆炸、飞刀、封锁不吃标记 | 不直接把全部范围伤害统一乘1.2 |
| 统一有效参数入口与完整机制说明 | 卡宾、泵动尊重DemoConfig，其他枪读取WeaponCatalog | 先统一引用，再考虑改弹匣或补给倍率 |
| 加入定向试用与合法配装路线卡 | 四职业枪池、双枪、一项职业技能、一项盾或刀；配件免费 | 重装第三批内容按真实需求判断，不先加同质枪 |
| 分开采购、尝试、结算记录 | 价格、奖励、保障与失败恢复 | 重玩、支线、后期收入和技能成本分别单项试验 |

### 1.2 系统闭环

~~~mermaid
flowchart LR
    A["关外选择与商品说明"] --> B["定向试用与配装路线"]
    B --> C["返回商品 自主采购"]
    C --> D["冻结出发快照"]
    D --> E["动作 伤害 控制与空间规则"]
    E --> F["任务目标与遭遇压力"]
    F --> G["成功结算与资源说明"]
    G --> A
    E --> H["本地尝试与耗用记录"]
    F --> H
    G --> H
    H --> I["针对一个问题调参"]
~~~

三项共同约束：

- 试用结果不授予正式资产，不改变正式职业、配装、库存和章节。
- 事件与表现一致：未出膛不扣弹，未完成装填不补弹，预告时间不因无关受击而偷偷变化。
- 奖励在成功持久化结算后成立；推荐、试用和记录工具都不成为第二个发奖入口。

## 2 首轮基线与参数冻结

| 系统 | 保持的数值或规则 | 作用 |
|---|---|---|
| 换位 | 双向交换位置，保留生命、装备与朝向；两端净空、视线和干扰终检 | 维持共同空间操作 |
| 配装 | 双枪不能同名且须合法；职业技能二选一；盾或投刀二选一，普通近战独立 | 保留长处和短板 |
| Boss | 能量360、生命720；能量归零及生命降到360为阶段阈值 | 保留三段资源结构与原技能池 |
| 收益 | 重玩50，可选40；第k章首通总计200＋15×(k−1) | 不因最高耗用组合65就判定所有重玩都亏 |
| 技能费用 | 基础100，强化100／160 | 先改善购买判断与试用 |
| 道具 | 医疗20／40HP／最多2；弹药25／双枪各两基础弹匣备弹／最多1；护甲25／40／最多1 | 两个不同类型槽提供携带取舍 |
| 资产保护 | 采购先保存，成功扣实耗，死亡重试与退出恢复采购后的库存 | 延续现有失败成本 |
| 关卡 | 主目标、指定必清、出口；无击杀赏金；永久退路；Boss随从预警加存活最多2 | 支持绕行、断援和遗留敌人撤离 |

冻结数值不代表难度必然不变。Boss不再被短硬直拖慢后，技能会按原时长执行，压力可能提高；这项影响需要针对性检查。

既有48行经济路径继续作为当前规则的证据，不重复未受影响的旧检查。未来改价格或奖励时，只复核受到影响的采购时点、余额和结算。

## 3 统一有效参数与伤害定义

### 3.1 同一参数服务战斗 补给与图鉴

建立轻量的有效武器基础参数解析入口，优先复用现有类型，不先建设通用数值框架。

| 使用位置 | 读取内容 |
|---|---|
| 开火和装填 | 机制、基础伤害、射速、弹丸数、基础弹匣、备弹上限、装填时间 |
| 弹药包 | 同一基础弹匣乘2；实际补入受缺口与备弹上限限制 |
| 图鉴 | 同一基础值，另外说明组内间隔、蓄能和射后恢复 |
| 配装与试用 | 基础值加合法配件和选定技能条件，保留各项来源 |
| 记录 | 规则版本、商品ID、配置条件，不将临时效果写成基础值 |

当前卡宾、泵动的实际弹匣可读DemoConfig，弹药包却读WeaponCatalog。两处现值相同，本期先统一引用链，保持原配置优先级。

**验收例：**在隔离配置中把卡宾弹匣24改为30，实战容量和图鉴都为30；备弹缺口足够时弹药包补60。扩容备弹仍只提高备弹上限，不变成扩大弹匣。

基础属性、配件结果和临时技能结果分开说明，不用一个混合DPS条给所有机制排序。

### 3.2 伤害按独立维度填写规则

| 维度 | 规则必须回答的内容 |
|---|---|
| 命中方式 | 枪弹、基础近战、飞刀、爆炸、持续区域怎样确定命中 |
| 增伤资格 | 是否计算部位、是否吃标记、是否消费首发强化 |
| 承伤顺序 | 常规、空间或环境类型；适用减伤、护甲、生命如何依次处理 |
| 屏障判定 | 敌方实体盾、Boss能量层、玩家A盾各自是否作用 |
| 空间条件 | 遮挡、同层、半径、距离端点和自伤 |
| 生命周期 | 预告、执行、独立飞行物在暂停、死亡、离场时如何处理 |

伤害类别与“能否被A盾拦截”是两个独立条件，不能仅改成常规伤害就默认允许A盾抵挡。

**标记首选保持：**首发命中后标记5秒，后续枪弹与基础近战加20%。不扩展到榴弹、遥控爆破、封锁、飞刀。范围伤害继续凭覆盖、几何和停留时间体现价值，并照常进入Boss能量层。

文案明确写出作用类型。未发射的余弹不补播特效；未完成装填不播放成功入匣反馈；标记、沉默、硬直不统一写成模糊的“控制成功”。

## 4 Q与其他动作的兼容契约

### 4.1 仲裁顺序

1. 暂停、死亡和离场优先处理，不启动新战斗动作。
2. 推进既有动作到本帧时刻，保留已经发生的出弹、命中和弹药转移。
3. 收集新输入，先对Q初检。
4. 初检合法则接受Q，进入准备并执行互斥；初检非法则按原流程处理其他输入。
5. 准备结束做终检，执行换位或失败恢复；由实际事件驱动表现与记录。

已进入Q准备后，每一帧继续遵守下表，不只屏蔽接受请求的第一帧。本期只统一与Q有关的兼容性；没有Q参与的其他动作顺序保持现行行为。

### 4.2 兼容矩阵

矩阵涵盖不同职业，不表示一套配装同时拥有所有能力。

| 状态或输入 | Q被接受后的行为 | 资源与时间 |
|---|---|---|
| 同帧新开火、近战、投刀 | 不启动新攻击 | 不扣对应弹药或冷却，不自动补发 |
| 三连发已经出首弹 | 立即取消尚未发出的余弹，与协程恢复时机无关 | 只扣实际已发子弹；最早下一发为最后实际出弹＋0.28秒，其他更晚门槛保留 |
| 已在装填 | 准备窗口挂起剩余计时与弹药转移 | 成功Q取消未完成装填，失败续装；已完成转移保留 |
| 同帧新装填、切枪 | 准备期不启动 | 不排队，结束后由玩家重新输入 |
| 线圈真实蓄能中 | 拒绝Q | 主动松开取消蓄能后可请求；未出弹不扣弹 |
| 机动、扫描、精确等自身准备 | 可与Q共存 | 持续时间正常流逝，不刷新 |
| 挂起装填时使用快速装填 | 拒绝本次使用并说明原因 | 不扣技能冷却；先前已生效的快装冷却不退 |
| 新震荡、新世界实体或区域创建 | 准备期不启动新施放 | 不扣冷却，避免在不确定位置创建攻击或区域 |
| 已有飞刀召回、已有遥控装置引爆 | 允许命令继续 | 回刀追踪实际玩家位置，爆炸在装置实际位置发生 |
| 主动E交互 | 准备期不提交新交互 | 自动区域和接入判断仍依实际世界状态 |
| 原有盾、阵地、投射物、区域 | 各自继续运行 | 不随Q搬家，不刷新生命周期 |

取消的连发余弹即使终检失败也不补发；失败仍不扣成功换位冷却。反馈区分“换位未开始”“换位取消，装填继续”“换位成功，装填中断”。

### 4.3 实现边界

PlayerMotor、PlayerCombatTools和PlayerClassSkill共享本帧Q接受状态及动作编号。旧协程恢复前核对编号，防止取消后继续发射。无需新增跨场景消息总线或通用技能语言。

死亡、重开、离场清除挂起动作；暂停冻结游戏时钟。取消不回滚已经发生的伤害、弹药转移或交易。

## 5 Boss控制与转阶段保持一致

### 5.1 分开普通行为和空间技能时钟

| 控制来源 | 普通敌人 | Boss普通行为 | Boss空间技能 |
|---|---|---|---|
| Q、近战、标记短硬直 | 保持现时长，取最大剩余值 | 暂停相应追击与普攻 | 预告、执行、收招、阶段判定继续，不重锁危险区 |
| 震荡突击 | 保留普通控制 | 只打断正在进行的步枪连射 | 不取消空间技能 |
| 飞刀沉默 | 保留已定义效果 | 不统一禁用普通步枪攻击 | 预告可中断；执行不撤销；沉默期间不启动下一招 |

保留单次沉默3.2秒及结束后4.5秒抗性；持续期和抗性期重复命中不延时。被中断的预告进入正常收招，下一技能须同时满足收招与沉默结束。

执行不中断包括本招已承诺的持续波、激光和剩余弹幕序列，不是只留已生成子弹却取消同一技能的后半段。独立飞行物不因普通硬直、沉默或转阶段凭空消失。

### 5.2 资源阶段即时变化 招式按快照结束

- 能量、生命、溢出伤害和阶段标识立即结算，保留360能量、720生命与两个阶段阈值。
- 已进入预告或执行的招式，使用施放时的范围、方向、伤害和时间快照完成；下一招使用新阶段技能池。
- 切阶段不刷新旧预警，不把新阶段参数套到正在执行的伤害。
- 沉默仍可按规则中断预告；死亡终止当前活动技能与后续攻击生成。
- 已独立飞行的弹丸按生命周期结束，关卡离场统一清理。实现时按对象归属区分持续技能与独立弹丸。
- 高伤害可以跨阈值，不锁血，不强迫观看完整阶段。

**验收例：**满能量时承受400点有效伤害，应剩能量0、生命680，溢出40不丢失也不重复结算。

### 5.3 随从保持有限压力

继续按预警中加存活最多2名计算；取消只影响未落地预算，不无预告删除旧随从。新阶段预算可以等待，实际部署仍满足上限和预警。

本期保留“留早期随从管理压力”这一可行选择，Boss自身技能和地形反制承担阶段主考验。若实际观察表明它稳定消除后期挑战，再单独设计有预告的职责调整，不与控制时钟修复捆绑。

## 6 配装路线连接职业与关卡

### 6.1 用现有能力形成两条可解释路线

新增关外配装路线卡，不增加职业或技能槽，不赠送资产，不自动购买。下表为拟加入的引导内容，不是最优配装排名。

| 职业与路线 | 双枪 | 职业技能 | 通用技能 | 主要取舍 |
|---|---|---|---|---|
| 突击 突入撤离 | 冲锋枪＋双管 | 快速机动 | A盾 | 先抢位再攻击，攻击结束机动，盾不跟随Q |
| 突击 近身控场 | 卡宾＋泵动 | 震荡突击 | 飞刀 | 控制争取出手，仍受盾面、视线与冷却限制 |
| 重装 机动补弹 | 机枪＋卡宾 | 快速装填 | 飞刀 | 长火力与轻装转场分工，以控制代替部分防护 |
| 重装 定点守线 | 机枪＋重突 | 阵地加固 | A盾 | 固定正面防护，离区失去加固，空间伤害另行反制 |
| 侦查 信息择线 | 三连发＋射手 | 战术扫描 | A盾 | 信息帮助选路线，不允许穿墙Q或同场兼带精确 |
| 侦查 关键单点 | 射手＋栓狙 | 精确射击 | 飞刀 | 首发与控制配合，保留小弹匣和射后等待 |
| 远程 直击集火 | 线圈＋标记器 | 遥控爆破 | A盾 | 标记支援线圈，爆破承担另一种用途且不吃标记 |
| 远程 封锁拆解 | 榴弹＋卡宾 | 区域封锁 | 飞刀 | 范围与控制配合，保留自伤和剩余停留成本 |

路线卡按当前账号标出拥有、上架、资格、费用和会替换的槽位。只有全部条件合法且处于整备状态时才能应用配置，并先展示差异；缺项跳转商品，不触发自动交易。

### 6.2 成长阶段与内容预期

| 阶段 | 目标 | 本期连接 |
|---|---|---|
| 第1至3章 | 保障配置理解职业和Q，形成第一轮预算 | 先显示保障路线，零道具仍可部署 |
| 第4至6章 | 新枪、技能升级与补给竞争预算 | 展示已上架装备的用途和试用入口 |
| 第7至12章 | 主配装成型后尝试横向解法 | 比较另一技能、其他职业与现有配件，不加必买门槛 |

重装继续保留重突与机枪，第6章后的提示展示两条打法，不伪装成新枪解锁。其他职业也有相同的路线比较入口，保持组织一致、内容用途有差异。

### 6.3 关卡承接用途

- 第5章双塔：信息准备、远距处理、抢位对应不同顺序，节点改变通路。
- 第7章三岛：配装不替代搬锚规划，维护路线和本次进度锁存保护试错。
- 第8章三仓：近距、长线、折返承接不同工具，第三仓仍是额外资源与时间选择。
- 第10章断援：初始备弹减半，机动和Q可通过提前关站减少未来威胁。
- 第12章：正面防护、区域、高差和换位分别处理不同威胁，单一防御不包办所有技能。

装备上架不等于本章强制购买，原有任务推进和永久退路继续成立。

## 7 商店到定向试用的闭环

### 7.1 复用现有独立演示

已有快速体验能以独立临时档提供全职业、全枪和三级技能。首版复用这套种子与玩法，新增定向请求；不复制正式账号，不另建成长系统。

采用独立试用进程。正式窗口停留整备并暂不接受采购、部署，结束后恢复。自由快速体验入口继续保留。

### 7.2 进入与返回约束

| 环节 | 规则 |
|---|---|
| 进入条件 | 关外整备且无活动部署，战斗背包不能进入 |
| 请求内容 | 商品、合法职业、试用等级、固定场景、会话编号、规则版本、原页面与滚动位置 |
| 不传递 | 正式余额、库存、完整存档、首通及可导入资产 |
| 对比条件 | 双枪和技能合法；固定其他条件，只替换被比较项目 |
| 返回内容 | 商品和界面上下文、试用事件摘要；不含正式资产写入命令 |
| 返回结果 | 成功、死亡、主动退出、异常关闭均无正式收益，回原商品 |
| 采购 | 玩家重新点击，走现有交易入口，重新核验价格、上架、拥有与余额 |

返回读取当前正式状态，不用进入前的旧副本覆盖账户。正式职业、配装、携带和章节不因试用改变。

### 7.3 避免三级试用误导一级购买

默认展示“本次购买或强化将获得的等级”：未拥有技能默认一级，升级入口默认拟获得的下一等级。另提供同等级对比档，对比同职业两项技能。

现有三级种子仅在隔离会话中覆写本次配置等级。界面持续显示试用等级、正式等级与购买结果，例如“本次比较3级；购买基础技能得到1级100，升到3级另需260”。

不同等级结果不合成排行榜。比较武器时固定其他配置；跨职业商品使用其合法职业，但不切换正式账号的职业。

### 7.4 两类首版场景

1. 近距与转场：复用近距路线、掩体和盾线，提供侧后路线与合法Q载体，比较短窗输出、装填与移动。
2. 长视线与火力间歇：复用高位和长线区域，比较射程、首发准备、小弹匣与长火力窗口。

不加无敌或额外伤害，不要求打完整章，可随时返回。试用胜利不是购买前置。

结果描述配置、有效命中、出弹和装填、受击与控制、道具变化；不做“综合最强分”，不按伤害为零贬低扫描等信息技能。

### 7.5 进程与数据失败恢复

试用请求和返回上下文存于独立会话，只处理当前会话编号和规则版本对应的结果。子进程异常时恢复正式窗口；没有结果就说明未记录，不自动采购或补偿。

正式成长档与回执不因试用变化；正常日志和用户自行修改设置不纳入“所有文件必须字节不变”的错误检查范围。

## 8 三本账与反馈口径

| 账目 | 记录 | 明确分开 |
|---|---|---|
| 采购账 | 请求号、商品、数量、实付、余额和库存变化 | 同一请求重试与两笔合法购物 |
| 尝试账 | runId和attempt、开始结束、活动与暂停时间、结局、道具使用、有效治疗、补入备弹、护甲吸收 | 失败尝试临时使用与永久损失 |
| 结算账 | 持久化成功后的奖励、首通、最终实耗与回执 | 结算意图与保存成功 |

保留runSeconds和最好成绩原义，另记累计尝试时间。不用最终成功的一次时长代表总投入，也不用旧夹具60秒计算刷关效率。

记录含Normal／Trial／QA与规则版本，只使用本地记录，不新增账号或上传平台。可选目标记录进入、完成与资源状态；这些记录描述实际耗用，不自动证明未走支线的反事实。

诊断记录失败不能伪造测量成功，也不改变已完成的资产结算。采购和结算的持久化失败继续严格处理，不能降级为只写一条提示。

## 9 参数试验的启动条件

首轮不直接执行内部建议中的候选数值。先用规则、试用和记录解释问题，再选择一项。

| 项目 | 保持 | 试调条件 | 候选与影响 |
|---|---|---|---|
| 重玩维持 | 50与可选40 | 理解补给后仍有持续高耗补货困难 | 基础65至75或补贴10至15二选一；检查低耗短关与首通不被顺带抬高 |
| 可选目标 | 40 | 支线出现稳定增量时间、实耗或失败差异 | 40／60／80风险档，不同时改威胁 |
| 后期首通 | 每章递增15 | 单职业者缺少购买目标，横向展示不足以解释 | 仅第8至12章增幅0至5，前七章不动，检查收藏与容错 |
| 替代技能 | 基础100 | 等等级试用后首次替代仍主要被成本阻挡 | 单独评估一次性替代技能优惠，先定义适用范围，不全局降价 |
| 护甲 | 价格25、容量40 | 理解用途后在适合常规伤害的场景仍缺价值 | 价格20至25或容量40至50，只改一个 |

保障、资格与失败保护不作为补其他问题的调价工具。重玩按50＋可选40－成功实际耗用的替换成本判断；携带不收费，最高合法组合全耗65不是固定支出。

## 10 状态权威与档案兼容

### 10.1 各系统只有明确的职责

- 有效参数入口解释数值，图鉴和补给不自行生成另一份弹匣规则。
- 动作仲裁消费资源并发出事件，动画不反过来决定伤害。
- MissionRuntime决定目标与撤离资格，路线卡和试用不能直接通关。
- ExpeditionStore负责正式交易，界面不能绕过资格与出发快照。
- 试用共享商品与规则标识，不共享可回写的资产副本。

### 10.2 保留当前v6与历史记录

首轮保留v6格式及稳定职业、武器、技能、章节ID，不改写历史回执。试用上下文与尝试记录先放独立会话资料，避免无必要的主档迁移。

当前采购回执已有rulesVersion，出发快照没有独立规则版本字段。本期在运行上下文与日志记录程序规则修订，不假设现有档案已有此字段，不在一次活动部署中切换规则。

更换构建时结束当前进程；未结算行动沿现有中断恢复流程，先恢复采购后资源再回整备，不把旧战斗动作恢复到新规则半途。

旧v4/v5正式档继续只做预览和候选，未经另行确认不导入、不补偿。试用档也不是迁移来源。

## 12 实施任务与依赖

S为局部改动，M为跨两三个模块，L为状态与表现联合接线；仅作相对工作量。

| 任务 | 范围 | 前置 | 工作量 | 验收 |
|---|---|---|---|---|
| U0 规则和基线 | 把本方案矩阵固化为实现对照，记录保留值与规则修订 | 无 | S | 每条拟改行为都有事件顺序及验收编号 |
| U1 参数解析 | WeaponCatalog、DemoConfig、PlayerMotor、WeaponDisplayStats、ExpeditionRun | U0 | M | P1一致 |
| U2 Q衔接 | PlayerMotor、PlayerCombatTools、PlayerClassSkill、动作表现 | U0 | L | A1至A4，资源和音画同步 |
| U3 伤害与Boss | EnemyActor、BossEncounter、BossSpatialSkills、BossPresentation | U0 U2 | L | D1及B1至B3 |
| U4 记录口径 | 现有事件/回执，增加attempt时间和有效耗用，分模式 | U1 U2 U3 | M | E1，未保存不记结算完成 |
| U5 定向试用 | DemonstrationMode、TacticalDemoProfile、RunStorage和商店；建议新增请求/返回类型 | U1 U4 | L | T1至T3 |
| U6 路线与引导 | TacticalPrototypeRules、ExpeditionUI、WeaponLibraryUI；建议新增配置数据 | U1 U5 | M | L1，八条示例合法 |

现有文件是核实过的入口；“建议新增”表示职责建议，不声称该类型已经存在。不要为形式整齐先拆成多层框架。

阶段顺序：

1. **U0至U3：**先解决一局游戏内的动作、伤害、控制一致性。
2. **U4至U6：**连接选择、试用、采购与反馈，保持正式资产边界。
3. **U7至U8：**在具体场景中确认协同，再决定是否启动一项参数实验。

分阶段保存提交与候选构建。体验出现不可接受回退时，回退对应阶段的改动并保留记录；不清空正式档或撤销既有购买来让验收通过。

## 13 设计结果与交付边界

完成后应能连贯解释三条实际流程：

- 战斗：准备能力—请求合法Q—按固定契约取消或保留动作—在清楚的伤害和控制边界内反制。
- 成长：商品说明—目标等级试用—合法路线比较—返回商品—真实采购—冻结下一次行动配置。
- 反馈：尝试过程—持久化结算—区分现金与库存变化—决定下一次选型或单项调参。

本轮只交付升级方案和本地分支，不包含玩法实施。后续先生成本地候选，正式发布使用新版本，不覆盖v0.6.0 Release。内部方案始终与对外求职设计文档分开。
